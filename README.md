# 21 Bell — классический WebGL-слот

Браузерный однорукий бандит с тремя вращающимися барабанами и боковой ручкой.
Математика точно воспроизводит документированный автомат **21 Bell**
(Wizard of Odds, [«The 21 Bell slot machine»](https://wizardofodds.com/games/slots/appendix/5/)).
Только виртуальные монеты: никаких покупок, депозитов и вывода средств.

**Играть онлайн:** https://gmaker.github.io/TinyBellSlotMachine/ (GitHub Pages, деплой из `main` через Actions).

- vanilla JavaScript (ES modules) — без движков и фреймворков;
- **весь интерфейс тоже WebGL2**: в `index.html` только один `<canvas>` — корпус, барабаны,
  символы, ручка, LED-табло, кнопки, текст, таблица выплат и экран «монеты закончились»
  рисуются шейдерами; DOM-элементов в UI нет;
- `CanvasRenderingContext2D` не используется ни для чего: символы — процедурные SDF,
  запечённые в атлас через framebuffer;
- звук и музыка синтезируются на лету через **Web Audio API**;
- стартовый баланс 100 монет; ставка 1×, 5× или 10× монет за спин (переключатели внизу корпуса), выплата умножается на ставку.

## Команды

```bash
npm install        # опционально: ставит esbuild для минифицированного билда
npm run dev        # dev-server без зависимостей → http://localhost:5173/
npm test           # unit-тесты чистой математики (node --test)
npm run build      # production-сборка в dist/ (esbuild; без него — копия ES-модулей)
npm run preview    # раздаёт dist/ на http://localhost:4173/
```

Dev-режим: откройте `http://localhost:5173/?dev=1` — при старте выполняется `verifyMath()` (полный
перебор 8000 исходов), отчёт печатается в консоль, а внизу корпуса появляется бейдж `MATH OK`
с контрольными значениями. В консоли доступно `slot.verifyMath()` и `slot.enumerateOutcomes()`.

## Управление

| Действие | Как |
|---|---|
| Спин | потянуть красную ручку вниз (мышь / touch, Pointer Events), кнопка **SPIN** на корпусе, `Space` или `Enter` |
| Ставка | тумблеры **1× / 5× / 10×** под кнопкой SPIN (клавиши `1`, `2`, `3`); меняется только между спинами, по умолчанию 1× |
| Настройки | кнопка с шестерёнкой или `S`: музыка ВКЛ/ВЫКЛ, звуковые эффекты ВКЛ/ВЫКЛ и язык (ENGLISH / РУССКИЙ); все выборы сохраняются в `localStorage` |
| Звук | музыка и эффекты отключаются независимо в настройках; клавиша `M` глушит или включает сразу оба |
| Таблица выплат | кнопка **PAYTABLE / ТАБЛИЦА**, клавиши `T` / `P`; закрыть — **CLOSE**, `Escape` или клик вне панели |
| Новая игра | при нулевом балансе — кнопка **NEW GAME / НОВАЯ ИГРА**, `N`, `Space` или `Enter` (баланс снова 100) |

Язык интерфейса по умолчанию — английский; бандлы строк лежат в `src/ui/i18n.js` (`en`, `ru`),
добавить язык — добавить объект с теми же ключами.

Спин принимается только в состоянии `IDLE` и при балансе ≥ текущей ставки. Ставка списывается
в момент принятия, три целевых индекса выбираются `Rng` **до** начала анимации,
барабаны честно останавливаются на них слева направо с инерцией и отскоком.
`prefers-reduced-motion` укорачивает вращение и убирает тряску, не меняя результата.

    text/TextRenderer.js     immediate-mode текст: каждый штрих — квад с capsule-SDF в шейдере
  input/
    InputManager.js          Pointer Events + клавиатура → мировые координаты, события
    LeverController.js       drag/auto-pull ручки, порог запуска, пружинный возврат
  audio/

    MusicScheduler.js        бесконечный салунно-механический луп с look-ahead планировщиком
  ui/
    UiLayer.js               весь UI в WebGL: заголовок, подписи, статус, кнопки SPIN/таблица/настройки,

Ключевые решения:

- **Математика не зависит от рендера.** `SlotMath` — чистый модуль; `SpinController`
  выбирает индексы через инъецированный `Rng`, а `ReelSet` строит план анимации,
  который *не может* закончиться иначе, чем на выбранных стопах (это дополнительно
  проверяется при оценке результата).
- **Барабан — настоящий цилиндр.** Каждая лента — замкнутый сегментированный цилиндр из
  20 стопов вокруг оси X; вершинный шейдер поворачивает его на `uPosition` (в стопах),
  так что соседи сверху/снизу всегда соответствуют физической ленте с переходом 20 → 1.
  Затенение краёв и блик рассчитываются от угла на цилиндре, окно маскируется stencil-буфером.
- **Символы — SDF без 2D canvas.** Восемь символов рисуются функциями расстояния в
  фрагментном шейдере и один раз запекаются в RGBA-атлас (premultiplied alpha) через FBO;
  лента сэмплирует атлас. Двойные стопы показывают два уменьшенных знака в одной ячейке.
- **Табло монет** — 7-сегментный LED-шейдер прямо на корпусе; строка «СТАВКА · БАЛАНС»
  и статус спина — векторный текст.
- **Текст без шрифтовых текстур.** `StrokeFont` описывает глифы полилиниями в единичном
  боксе; `TextRenderer` превращает каждый штрих в квад и сглаживает его SDF-капсулой во
  фрагментном шейдере — текст остаётся резким при любом масштабе и DPR.
- **Иконки в таблице выплат** берутся из того же атласа символов, что и ленты.
- **Аудио** запускается только после первого жеста пользователя; шины music и sfx → master-gain →
  компрессор в роли лимитера. Музыка и эффекты глушатся раздельно (своя шина и свой ключ в
  `localStorage`); при выключенной музыке или скрытой вкладке планировщик нот останавливается.

## Математическая модель

Три физические ленты, на каждой **ровно 20 равновероятных стопов**; индексы выбираются
независимо и равномерно из `0..19`, всего `20³ = 8000` исходов.

### Почему двойные символы — это один физический стоп

На реальном автомате стоп вроде `7 + Orange` — это одно положение барабана, на котором
напечатаны два знака. Он засчитывается **одновременно** как `7` и как `Orange`, но занимает
ровно 1/20 вероятности. Если разбить его на два отдельных стопа, лента станет длиннее
(21 стоп), вероятности сдвинутся и контрольные значения (1073 выигрышных исхода, RTP 94,45 %)
перестанут сходиться. Поэтому в коде стоп — это массив из одного или двух символов,
а `stopMatches(stop, symbol)` проверяет вхождение.

### Таблица выплат (за ставку 1; при 5× и 10× выплата умножается; приоритет сверху вниз, платится одна старшая)

| # | Комбинация | Выплата | Исходов / 8000 | Вероятность |
|--:|---|--:|--:|--:|
| 1 | 7, 7, 7 | 200 | 1 | 0,0125 % |
| 2 | Bar, Bar, Bar | 100 | 6 | 0,0750 % |
| 3 | Melon, Melon, Melon | 100 | 8 | 0,1000 % |
| 4 | Melon, Melon, Bar | 100 | 4 | 0,0500 % |
| 5 | Bell, Bell, Bell | 18 | 40 | 0,5000 % |
| 6 | Bell, Bell, Bar | 18 | 5 | 0,0625 % |
| 7 | Plum, Plum, Plum | 14 | 63 | 0,7875 % |
| 8 | Plum, Plum, Bar | 14 | 21 | 0,2625 % |
| 9 | Orange, Orange, Orange | 10 | 100 | 1,2500 % |
| 10 | Orange, Orange, Bar | 10 | 25 | 0,3125 % |
| 11 | Cherry, Cherry, Any | 5 | 240 | 3,0000 % |
| 12 | Cherry, Any, Any | 2 | 560 | 7,0000 % |

`X, X, Bar` срабатывает, когда третий стоп *содержит* Bar — комбинированный `7 + Bar` тоже подходит.

### Контрольные значения (подтверждаются полным перебором в тестах и `verifyMath()`)

| Показатель | Значение |
|---|--:|
| Выигрышных исходов | 1073 / 8000 |
| Частота любого выигрыша | 13,4125 % |
| Сумма выплат за цикл | 7556 |
| RTP | 7556 / 8000 = 94,45 % |
| Вероятность проигрыша | 6927 / 8000 = 86,5875 % |
| Ожидание чистого изменения баланса за спин | −0,0555 монеты |

Проценты частот символов и все значения выше хранятся в коде только как *ожидаемые*
константы для верификации (`EXPECTED_*`); источник истины — сами ленты и таблица.

Без wild/scatter, бонусов, множителей, near-miss-манипуляций, динамических весов
и скрытого изменения RTP.

## Тесты

`npm test` запускает `node --test` по `tests/*.test.mjs`:

1. каждая лента — ровно 20 стопов, частоты символов совпадают с таблицей;
2. полный детерминированный перебор 8000 троек даёт ровно `1, 6, 8, 4, 40, 5, 63, 21, 100, 25, 240, 560`;
3. 1073 выигрышных исхода, сумма выплат 7556, RTP 0,9445;
4. двойные стопы и приоритет выплат (`7,7,7` через `7 + Bar`, `Bell, Bell, Bar`, `Melon ×3` через `Melon + Orange` и т. д.);
5. баланс: списание ставки (1/5/10) за спин, выплата × ставка начисляется ровно один раз, при нехватке монет спин невозможен, сброс к 100 и ставке 1;
6. seeded/scripted RNG даёт предсказуемые индексы; FSM проходит все фазы; барабаны
   останавливаются строго на целях для любого старта и цели.

## Известные ограничения

- Требуется WebGL2; при его отсутствии или потере контекста показывается единственный
  DOM-элемент с сообщением (создаётся из JS по факту ошибки), fallback-рендера нет
  (2D canvas запрещён условиями задачи).
- Поскольку UI полностью внутри canvas, экранные читалки видят только `aria-label` канвы;
  вся функциональность доступна с клавиатуры (Space/Enter, S, M, T, Escape, N).
- Шрифт — штриховой, только заглавные буквы (латиница, кириллица, цифры, знаки).
- Символы — стилизованные процедурные заглушки (SDF), а не иллюстрации.
- Музыкальный луп — короткий четырёхтактный паттерн; это осознанно «ненавязчивый фон».
- В Safari ниже 15 Web Audio может требовать дополнительного жеста для возобновления контекста.
